# IPC lifecycle

Source of truth: [`src/shared/ipc-contract.ts`](../src/shared/ipc-contract.ts). It must not import `zod` or `electron`, because the preload runs sandboxed and may only `require('electron')`.

## Window hardening

`src/main/window/create-main-window.ts`: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, `webSecurity: true`. `will-navigate` is blocked (except the dev server origin) and `window.open` only forwards `http(s)` URLs to `shell.openExternal`.

## Request/response (`invoke`)

```
React hook ──► window.api.<domain>.<method>()          (preload, typed by BakaSubApi)
          ──► ipcRenderer.invoke(channel, payload)      (channel checked against INVOKE_CHANNELS)
          ──► ipcMain.handle ── createHandler
                 1. isTrustedSender(event.senderFrame.url)   dev: ELECTRON_RENDERER_URL prefix, prod: file://
                 2. options.input.safeParse(raw)             Zod; INVALID_INPUT on failure
                 3. options.handle(payload, event)
                 4. envelope: { ok: true, data } | { ok: false, error: { code, message } }
          ──► unwrap() in the renderer throws IpcCallError ──► TanStack Query error state
```

- `AppError` (see `src/main/errors.ts`) is mapped to its stable `code`; any other exception becomes `INTERNAL` and is logged with the `ipc` scope.
- The renderer never receives the Electron `event` object nor `ipcRenderer`.

## Push events (main → renderer)

`emitToRenderers(channel, payload)` (`src/main/ipc/events.ts`) sends to every live window. The preload exposes `window.api.events.on(channel, listener)`, which validates the channel against `EVENT_CHANNELS` and returns an unsubscribe function. Channels: `sidecars:progress`, `app:update-state`, `jobs:progress`, `logs:entry` and `app:navigate` (a click on a native notification, see [`notifications.md`](./notifications.md)).

## Adding a channel

1. Add the entry to `IpcInvokeContract` (or `IpcEventContract`) and to the matching allowlist array.
2. Add the method to `BakaSubApi` and wire it in `src/preload/index.ts`.
3. Create or extend a file in `src/main/ipc/handlers/` calling `createHandler(channel, { input?, handle })`, and register it in `src/main/ipc/register.ts`.
4. Consume it from a hook in `src/renderer/src/hooks/` using `unwrap()`.

## Auto-update contract (frozen)

Types live in `src/shared/ipc-contract.ts`; the service is `src/main/services/app-updater.ts`.

States (`AppUpdateState`): `idle | checking | available | not-available | downloading | downloaded | error | unsupported`.

```ts
interface AppUpdateStatus {
  state: AppUpdateState
  current: string
  latest?: string // from `available` on
  publishedAt?: string // ISO 8601
  notes?: string // GitHub release body as HTML, max 20k chars; UNTRUSTED, sanitize before rendering
  size?: number // bytes
  progress?: { percent; transferred; total; bytesPerSecond } // only `downloading`
  error?: { code; message } // only `error`; code is `NETWORK` (offline: true) or `INTERNAL`
  offline?: boolean
  fallbackUrl?: string // only `unsupported`; passes `isAllowedExternalUrl`
}
```

Transitions: `idle → checking → available | not-available | error`; `available → downloading → downloaded | error`; `downloading → available` on cancel; `error` is not terminal (a new check works). `unsupported` is permanent for the process (dev build, Linux outside an AppImage, macOS) and never touches the network or logs an error.

Rules the UI can rely on:

- Nothing is downloaded without `app:download-update` and nothing is installed without `app:install-update`. `quitAndInstall` exists only inside `app:install-update`; a normal quit never installs.
- `app:check-update` is a no-op in `downloading`/`downloaded`/`unsupported` (returns the current info) and coalesces concurrent calls.
- `app:install-update` with running jobs: `UPDATE_JOBS_ACTIVE` unless `confirmJobs: true`. With confirmation the Main aborts jobs (marked `interrupted`, re-queued on the next boot), disposes sidecars/Job Memory/DB through the `ShutdownCoordinator`, then installs and relaunches.
- A silent automatic check runs once per session, `AUTO_CHECK_DELAY_MS` (3 s) after it is armed, when `updates.autoCheck` (default `true`) is on. It only emits `app:update-state`; it never downloads.
- Onboarding gate (`scheduleAutoCheck`): the Main evaluates the shared rule `isOnboarded` (`src/shared/onboarding.ts`: API key + `translation.defaultModel` + `translation.defaultTargetLang`, the same one the router guard uses) at boot. Already onboarded: armed at boot. Otherwise nothing is checked while `/welcome` is open, not even after the required steps pass mid-wizard (optional steps follow them); the wizard's "Finish" sends `app:onboarding-finished` (`{ acknowledged: true }`, idempotent), which re-evaluates the rule and arms the check. A rule read failure defers instead of checking. `app:check-update` (Settings → About) is never gated.
- `AppUpdateInfo` (from `app:check-update`) keeps its old fields (`current`, `latest`, `updateAvailable`, `publishedAt`, `offline`) and adds optional `notes`, `size`, `state`, `fallbackUrl`, `error`.
